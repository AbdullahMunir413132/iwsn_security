# IWSN Security — DPI + IDS + MQTT Analysis Platform

Industrial Wireless Sensor Network security analysis system. Single unified binary performs Deep Packet Inspection, Intrusion Detection, and MQTT protocol analysis in one pipeline, tuned for micro-networks of 2–4 ESP32 sensor nodes.

---

## Quick Start

```bash
# Build
cd c_dpi_engine && make

# Analyze a PCAP
./bin/iwsn_analyzer ../scripts/attack_samples/syn_flood.pcap

# Or run the full pipeline (simulate → analyze → report → export)
../scripts/run_pipeline.sh
```

## Pipeline Overview

```
 ┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌────────────┐
 │  PCAP / Live  │───▶│  DPI Engine   │───▶│  Rule Engine  │───▶│ MQTT Parser│
 │   Capture     │    │  (nDPI L2-5)  │    │  (IDS / IPS)  │    │ (Payloads) │
 └──────────────┘    └──────────────┘    └──────────────┘    └────────────┘
                                                                     │
                           ┌─────────────────────────────────────────┘
                           ▼
                    ┌──────────────┐    ┌──────────────┐
                    │  3 Reports   │───▶│   Grafana    │
                    │  (DPI/IWSN/  │    │  Dashboard   │
                    │   MQTT)      │    │  (Prometheus) │
                    └──────────────┘    └──────────────┘
```

## Output: 3 Consolidated Reports

| Report | Contents |
|--------|----------|
| `reports/Full_DPI_Report.txt` | All flows, protocols, packet layers (L2–L5), throughput |
| `reports/Full_IWSN_Report.txt` | IDS attack detections + performance metrics + accuracy |
| `reports/Full_MQTT_Report.txt` | MQTT messages, topics, sensor payloads, session data |

Generated by `scripts/run_pipeline.sh` or manually via the binary + consolidation.

## Master Pipeline Script

```bash
scripts/run_pipeline.sh                       # Full: simulate → analyze → report → Grafana export
scripts/run_pipeline.sh --pcap file.pcap      # Analyze existing PCAP
scripts/run_pipeline.sh --live                # Live capture (needs sudo)
scripts/run_pipeline.sh --simulate-only       # Generate attack PCAPs only
scripts/run_pipeline.sh --export-only         # Re-export reports to Grafana
```

## Attack Simulator

Scapy-based generator tuned for 2–4 node micro-IWSN. Produces per-attack and combined PCAPs.

```bash
# Generate all attack PCAPs (offline)
python3 scripts/attack_simulator.py

# Live injection mode (requires root + interface)
sudo python3 scripts/attack_simulator.py --live --iface wlan0 --attack syn_flood --target 10.7.88.12
```

**21 attack classes**: SYN/UDP/ICMP/HTTP floods, SYN/Connect/UDP/Xmas/NULL/FIN scans, Ping of Death, Teardrop, Smurf, Fraggle, DNS/NTP amplification, ARP/IP spoofing, Slowloris, RUDY, plus normal & MQTT baselines.

## ESP32 Sensor Node

Quad-sensor firmware for ESP-WROOM-32D (2× SONAR SR04M-2 + 2× IR object detectors).

```
hardware/esp32_node/
├── esp32_quad_sensor.ino      # Main firmware
└── credentials.h.example     # WiFi/MQTT template (copy → credentials.h)
```

**Features**: NTP-synced ISO 8601 timestamps, multi-level alerts, heartbeat with diagnostics, auto-reconnect.

**MQTT topics** (per node):
- `iwsn/sensors/{NODE_ID}/sonar_1`, `sonar_2`, `ir_1`, `ir_2`
- `iwsn/sensors/{NODE_ID}/combined`, `heartbeat`, `online`

## Detection Thresholds (Micro-IWSN Tuned)

Thresholds are calibrated for 2–4 sensor nodes to eliminate false positives under normal MQTT heartbeat traffic:

| Attack | Threshold |
|--------|-----------|
| SYN Flood | 15 SYN/sec per IP |
| UDP Flood | 30 packets/sec |
| ICMP Flood | 20 packets/sec |
| HTTP Flood | 10 requests/sec |
| Port Scan | 5 unique ports |
| Smurf/Fraggle | 10 broadcast packets |
| Slowloris | 2 concurrent connections, 20s min |
| RUDY | 5 min packets, 20s duration |
